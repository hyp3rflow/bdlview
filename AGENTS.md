# AGENTS.md - BDL Viewer

Guidelines for AI agents working on this codebase.

## Project Overview

BDL Viewer is a web-based viewer for BDL (Bridge Definition Language) schemas, similar to Swagger/Redocly but for BDL. It connects to a BDL reflection server and displays types, procedures, and namespaces.

### Tech Stack
- **Vite + React 19 + TypeScript** with pnpm
- **PandaCSS** for styling (generates `styled-system/`)
- **jotai + jotai-tanstack-query + bunja** for state management
- **@disjukr/bdl** from JSR for BDL types

## Code Style Guidelines

### Imports
Order imports as follows:
1. React and React hooks
2. Third-party libraries (jotai, tanstack-query, bunja)
3. PandaCSS imports from `../../styled-system/css`
4. Local modules (atoms, api, types)
5. Type-only imports with `import type`

```typescript
import { useState, useCallback, useEffect } from "react";
import { useAtom, useAtomValue } from "jotai";
import { css } from "../../styled-system/css";
import { serverUrlAtom } from "../atoms/bdl";
import type { Def, BdlIr } from "../types/bdl";
```

### TypeScript
- Use explicit types for component props via interfaces
- Prefer `type` for unions and simple types, `interface` for objects with methods
- Use `Extract<T, U>` for narrowing discriminated unions
- Always use `type` keyword for type-only imports

```typescript
interface SidebarProps {
  onSelectDef: (defPath: string) => void;
  selectedDefPath: string | null;
  ir: BdlIr | null;
}

// Discriminated union narrowing
function StructView({ def }: { def: Extract<Def, { type: "Struct" }> }) {}
```

### Naming Conventions
- **Components**: PascalCase (`DefDetail`, `NamespaceView`)
- **Functions**: camelCase (`createBdlClient`, `handleSelectDef`)
- **Atoms**: camelCase with `Atom` suffix (`serverUrlAtom`, `selectedStandardAtom`)
- **Bunja**: camelCase with `Bunja` suffix (`bdlBunja`)
- **Scopes**: camelCase with `Scope` suffix (`serverUrlScope`)
- **Types/Interfaces**: PascalCase (`BdlIr`, `SidebarProps`)
- **Event handlers**: `handle` prefix (`handleClick`, `handleSelectNamespace`)
- **Callbacks as props**: `on` prefix (`onSelectDef`, `onTypeClick`)

### Styling with PandaCSS
Use the `css` function for all styles. Prefer inline styles in `className`:

```typescript
<div
  className={css({
    display: "flex",
    flexDirection: "column",
    gap: "4",
    p: "5",
    bg: "#FFFFFF",
    borderRadius: "lg",
    _hover: { bg: "#F5F3EF" },
  })}
>
```

- Use design tokens where possible (`"4"` for spacing, `"lg"` for border-radius)
- Use hex colors directly for custom colors (e.g., `"#D97706"` for orange accent)
- Use pseudo-class props (`_hover`, `_focus`) instead of CSS selectors

### Component Patterns
- Export named functions, not default exports for components (except `App`)
- Use `useCallback` for event handlers passed to child components
- Use `useMemo` for expensive computations
- Prefer controlled components with state lifted to parent

```typescript
export function Sidebar({ onSelectDef, selectedDefPath }: SidebarProps) {
  const handleClick = useCallback((path: string) => {
    onSelectDef(path);
  }, [onSelectDef]);
  // ...
}
```

### State Management
- Use **jotai** atoms for global state
- Use **bunja** for scoped dependency injection (e.g., scoped by server URL)
- Use **jotai-tanstack-query** (`atomWithQuery`) for async data fetching

```typescript
// Scope definition
export const serverUrlScope = createScope<string>();

// Bunja with scoped dependencies
export const bdlBunja = bunja(() => {
  const serverUrl = bunja.use(serverUrlScope);
  const client = createBdlClient(serverUrl);
  // ...
});
```

### Error Handling
- Use descriptive error messages with context
- Throw errors for API failures with status text
- Display errors in UI with appropriate styling

```typescript
if (!response.ok) {
  throw new Error(`Failed to fetch modules: ${response.statusText}`);
}
```

### BDL Path Format
Definition paths use dots.
To extract namespace from def path:
```typescript
const namespacePath = defPath.split(".").slice(0, -1).join(".");
```

## Key Features

1. **Two view modes** (toggle in top-right):
   - **Explorer**: Navigate namespaces depth-by-depth with breadcrumbs
   - **Overview**: See all definitions at once, scroll to sections

2. **File View** (for leaf namespaces):
   - Automatically shown when selecting a leaf namespace (has definitions but no child namespaces)
   - **Definitions tab**: Shows all definitions inline with their details
   - **Source tab**: Shows BDL source code with syntax highlighting

3. **Sidebar**: Tree view with:
   - Folder icons for namespaces, file icons for leaf namespaces
   - Type tags (rpc, s, e, u, o, t) with colors
   - Search functionality
   - Auto-expand single-child chains

4. **Browser history**: Back/forward navigation via `pushState`/`popstate`

## API Endpoints (BDL Reflection)

The client expects these endpoints on the configured server:

- `GET /bdl/standards` - List available standards
- `GET /bdl/standards/:id` - Get standard details
- `GET /bdl/standards/:id/ir` - Get IR (intermediate representation)
- `GET /bdl/modules` - List modules
- `GET /bdl/modules/:path/text` - Get module source text
